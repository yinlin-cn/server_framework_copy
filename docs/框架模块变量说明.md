# 框架模块变量说明

本文按模块列出当前 `aggregation/` 中的核心字段、结构和线程归属。局部变量、标准库内部实现不展开。

## 1. 网络层

### Acceptor

文件：`Acceptor.h` / `Acceptor.cpp`

| 名称 | 类型 | 作用 |
|---|---|---|
| `listen_fd_` | `int` | 监听 socket，只负责接收新连接 |
| `epoll_fd_` | `int` | Acceptor 自己的 epoll，监听 `listen_fd_` 和 `wake_fd_` |
| `wake_fd_` | `int` | 停止 Acceptor 时唤醒 `epoll_wait` 的 eventfd |
| `port_` | `int` | 监听端口 |
| `backlog_` | `int` | `listen()` 的 backlog |
| `factory_` | `Handler_epoll_Factory*` | 为新连接创建连接级 Handler |
| `reactors_` | `vector<shared_ptr<Reactor>>` | 新连接轮询分配的目标 Reactor |
| `events_` | `vector<epoll_event>` | `epoll_wait` 输出缓冲 |
| `listen_event_id` | `uint64_t` | 监听事件的 epoll token |
| `wake_event_id` | `uint64_t` | 停止事件的 epoll token |
| `next_` | `atomic<uint64_t>` | Reactor 轮询分配游标 |
| `running_` | `atomic<bool>` | Acceptor 线程运行状态 |
| `thread_` | `thread` | Acceptor 事件线程 |

关键函数：

- `start()`：创建 listen socket、epoll、eventfd，注册监听事件。
- `handle_accept()`：一次接收所有已排队连接，直到 `EAGAIN`。
- `event_loop()`：等待 listen 事件或停止事件。
- `wakeup()`：向 `wake_fd_` 写值。
- `stop()`：置停止标志、唤醒 epoll、join 线程并关闭 fd。

| `metrics_` | `Handler_metrics*` | 指标接口 |
| `log_` | `Handler_log*` | 日志接口 |

关键函数：

- `add_connection()`：登记连接、执行 `on_connect`、加入 epoll。
- `handle_read()`：读取数据并拆包，按窗口状态投递消息。
- `try_send()`：批量写出同连接的发送队列。
- `pause_reading()` / `schedule_resume()`：背压暂停与恢复。
- `request_close()` / `close_client()`：把关闭动作收口到 Reactor 线程。
- `event_loop()`：处理 wake、读写、错误和心跳扫描。

## 7. 读代码时的主线

```text
Acceptor
  -> 新连接轮询分配给 Reactor

Reactor
  -> read_buffer 拆包
  -> Handler_epoll_make
  -> divide_pool
  -> divide_task.back_funtion()
  -> work_pool
  -> work_task.fn()

query_db
  -> EventAwaiter 挂起
  -> Box + wait_key
  -> DB_pool
  -> 恢复任务回到 work_pool
  -> handle.resume()

send
  -> Internalconnection.send_queue
  -> pending_send_
  -> BatchSender 唤醒
  -> Reactor.try_send()
```

先看 `Server` 的成员组装，再看 `Server::start()` 和 `Server::stop()`；之后每个模块只看它自己的字段和关键函数，就能知道自己处于主线的哪一段。
