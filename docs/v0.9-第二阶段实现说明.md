# v0.9 第二阶段实现说明

本文记录多 Reactor 网络层、背压恢复和协程稳定性在第二阶段的实际改动，内容以当前 `aggregation/` 代码为准。

## 1. Acceptor 与 Reactor 都是 epoll

当前网络层不再是单线程 accept 轮询。

### Acceptor

- `listen_fd_` 加入 Acceptor 自己的 `epoll_fd_`；
- `wake_fd_` 是 eventfd，用于停止时唤醒 `epoll_wait`；
- `event_loop()` 等待 listen 事件；
- `handle_accept()` 循环 `accept()` 到 `EAGAIN`；
- `EMFILE/ENFILE` 退避重试；
- `start()` 返回 `bool`，启动失败会回滚。

### Reactor

- 每个 Reactor 一个 `epoll_fd_`、一个 `wake_fd_`、一个事件线程；
- 客户端事件使用 `reactor_conn_id` 作为 epoll token；
- `wake_fd_` 负责跨线程的发送、恢复、关闭和 divide 重试请求；
- 业务线程不直接操作 epoll。

## 2. 跨线程发送与 EPOLLOUT 是两条路径

### 业务线程发送

```text
send()
  -> Internalconnection::send_function
  -> enqueue_send()
  -> pending_send_
  -> Handler_batch::on_need_send()
  -> BatchSender 去重
  -> Reactor::wakeup()
  -> event_loop 的 wake_event_id
  -> 扫描 pending_send_
  -> try_send()
```

业务线程只入队，不直接 `write()`。

### Socket 可写恢复

`try_send()` 如果遇到半截写或 `EAGAIN`：

```text
残余数据回插 send_queue
  -> 注册该连接的 EPOLLOUT
  -> 内核可写时只唤醒该连接所属的 Reactor
  -> try_send() 继续发送
```

`EPOLLOUT` 是 socket 级可写事件，不是跨线程信号。每个连接只注册在一个 Reactor 的 epoll 中，不会产生跨 Reactor 惊群。

## 3. 背压队列与低水位回调

`bounded_task_queue<T>` 当前提供：

- `try_push()`：非阻塞；
- `push()`：队列满时阻塞；
- `pop()`：取出任务；
- `close()`：关闭队列并唤醒所有人；
- `set_low_water_callback()`：队列降到低水位后回调。

`pop()` 到低水位时会调用回调，由 `divide_pool` 接到网络层：

```text
bounded_task_queue::pop()
  -> divide_pool low water callback
  -> NetworkServer::retry_paused()
  -> Reactor::retry_pending()
  -> Reactor::process_divide_retry()
  -> Reactor::handle_read()
```

## 4. divide 队列满时不再阻塞 Reactor

`Handler_epoll_make::on_message()` 对 divide 队列使用 `try_add_task()`。

当结果不是 `push_result::Ok` 时直接返回，不再调用阻塞版 `add_task()`。

Reactor 收到 `push_result::Full` 后：

```text
归还 ConnectionFlow 窗口位
-> 消息重新放回 conn->read_buffer
-> 加入 Reactor::pending_divide_retry_
-> reading_paused = true
-> 等 divide 队列低水位回调
-> 重试 handle_read()
```

因此队列满时只暂停具体连接，不暂停整个 Reactor。

## 5. ConnectionFlow 状态机修复

`release_slot()` 现在只归还窗口位：

```cpp
if (in_flight_ > 0)
    in_flight_--;
if (full_ && in_flight_ < window_)
    full_ = false;
```

它不再设置没有对应 `schedule_resume()` 的 `resume_pending_`。

窗口满后的恢复流程：

```text
work worker finish
  -> ConnectionFlow::finish_one()
  -> owner_reactor->schedule_resume()
  -> pending_resume_
  -> Reactor::process_pending_resume()
  -> ConnectionFlow::consume_resume()
  -> handle_read()
```

## 6. 协议重同步和读缓冲上限

`Reactor::take_one_message()` 当前是主解析路径：

- 从当前位置查找合法 4 位长度头；
- 跳过非法字节；
- 正文不完整时保留数据；
- 正文完整时消费消息；
- `read_buffer` 超过 1MB 时关闭连接；
- 单帧限制为 4 位长度头可表达的 9999 字节。

`peek_one_message()` 和 `spilit_message()` 只保留为旧实现，不在主处理路径中。

## 7. 协程挂起屏障

协程不再使用自旋等待。

`Box` 持有：

```cpp
std::shared_ptr<coroutine_suspend_guard> suspend_guard;
```

业务 worker 执行完业务函数后：

```cpp
active->finish();
```

DB worker 投递恢复任务前：

```cpp
job.box->suspend_guard->wait_finished();
```

该机制保证协程真正挂起完成后，DB 才会投递恢复任务。

## 8. 发送队列和心跳

- `Internalconnection::queued_send_bytes` 记录发送队列的待发总字节数；
- 单连接发送队列默认最多约 4MB；
- 超出上限时 `send_function` 返回 false；
- `try_send()` 成功写出后刷新 `last_active_us`；
- 纯推送连接不会因为只写不读而被空闲心跳误杀。
